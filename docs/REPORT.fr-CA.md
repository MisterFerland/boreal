# BOREAL — synthèse opérationnelle

BOREAL est un démonstrateur de portfolio indépendant d’Yves Ferland. La politique, les données et les règlements sont fictifs. Aucune affiliation gouvernementale, autorisation, certification ni connexion à un système de paiement réel n’est revendiquée.

Le programme fictif **Remboursement des infrastructures communautaires** rembourse75% du coût admissible, arrondi au cent par excès à la moitié, jusqu’à2500,00CAD. La politiqueV2 à80% sert uniquement à la comparaison. Le moteur COBOL natif effectue la validation, les contrôles, le calcul, les propositions d’écritures et les classifications de rapprochement.

L’opérateur importe et examine; un approbateur distinct autorise la comptabilisation; l’auditeur exporte les preuves. Les entrées, résultats et approbations sont figés. Une reprise après interruption utilise les reçus de segments et les clés financières uniques pour produire un seul effet financier validé par clé métier malgré les tentatives répétées.

Le dossier de preuves ZIP contient les octets originaux, empreintes, résultats canoniques, versions du moteur et des règles, écritures, exceptions et vérification d’audit. Les identifiants techniques restent stables dans les deux langues. Les rapports JSON conservent les valeurs exactes et la méthode de mesure. La chaîne de hachage ne protège pas contre la réécriture privilégiée de toute la chaîne et de son ancre.

L’interface vise les WCAG2.2 niveauAA. Les vérifications automatisées et les parcours clavier sont consignés; une évaluation complète avec lecteur d’écran reste non vérifiée. Les obligations d’une institution ou d’un contrat doivent faire l’objet d’une évaluation distincte.

Consultez `artifacts/verification.json`, `artifacts/backup-restore.json`, `artifacts/accessibility.json` et les rapports de performance pour les résultats réellement exécutés. Aucun résultat de performance n’est extrapolé vers un ordinateur central.
